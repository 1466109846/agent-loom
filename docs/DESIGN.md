# Loom 设计文档

Loom 帮助编码助手回答三类问题：这个项目想做什么；改一处代码会影响谁；以前为什么做过这个决定。三类答案的依据不同，不应写成一份越来越长的项目摘要。

**项目知识按三种方式交付：开工时只给确认过的约束，用到时查源码与经验，中断后恢复未完成任务。** 本地实现已打通这三条路径；U-1 查询可信度、U-2 固定评测和 U-3 显式 `context` 已实现并完成本机验收（2026-11-26），质量与同场资源比较 PASS（198 checks），Loom 已接入本机 ZCode。同日加入三项：库可以放在任意磁盘位置并能迁移；接入、搬库和配模型的步骤随程序分发，由助手执行；可选的向量检索与重排，默认关闭（第 12 节）。结构查询仍是上次显式更新的快照；可选模型的真实收益和全新环境的首次接入分别验收。

设计目标与当前行为的差距、已有实现仍欠的验收、明确不在范围内的事项，集中在[第 13 节：预期欠账](#design-debt)。

## 1. 目标与取舍

- 一个项目用一个本地库。默认只需启动一个进程，就能保存、管理和检索记忆；不依赖网络，也不要求先把整个项目交给模型阅读。库默认放在项目里，也可以放在用户选定的任意位置。本次以 Loom 承担项目记忆与恢复，替代 memos 的日常职责；memos 服务不是运行依赖，旧 wiki 只作可选的只读迁移输入。
- 助手开工前应知道项目目标和不可违反的约束。平时先给结论、出处和查找入口，读者需要时再看模块、文件、符号或记忆全文。**能查到，不等于每次都要展示。**
- 结构事实尽量从源码确定；原因由人或助手记录。找不到依据时回答“不知道”，不拿历史摘要代替当前代码，也不从代码外观猜项目目标。
- 资源目标是空闲进程内存低于 100 MB，处理五万行源码时峰值低于 300 MB。不为等待文件变化常驻扫描，也不为少量关系启动独立的存储进程。这些数字是验收目标，不是对任意项目的性能承诺。
- 不做跨项目的私人知识汇总，不追求完整的运行时调用图。短期任务中间态不默认进入长期记忆。

## 2. 当前有什么，还缺什么

| 能力 | 本地实现已有 | 尚未交付或尚待实测 |
|---|---|---|
| 经验与证据 | 写入、检索、取代和归档；源码变化提示、保留原编号的近似项折叠、人工声明的支持与冲突、按任务恢复下一步；可选的向量检索与重排，按项目启用 | 大规模资料的成批复核；真实模型对不同问法的收益 |
| 意图与会话 | 提议经人确认才生效；开场先给红线、目标及显式置顶项，重复请求只给快照编号；没有可靠计量约定时不自动注入；项目没绑定时会话服务仍可启动并引导助手接入 | 不同宿主实际接入、各种分词口径的端到端验证 |
| 项目与代码 | 根目录与库双向核对，库的位置可记住、可迁移；显式刷新结构快照；双向查询带使用方行号、代次、覆盖与有界核对；以源码指纹撰写和复核人工职责；只读 `context` 按任务组合约束、结构、职责与经验 | Rust 跨 crate `use` 召回、外部/标准库导入分类；更多工程布局和语言、目录级聚合、精确符号调用关系 |
| 数据迁移与分享 | 旧文本只读导入；逐条选定的有效意图和经验可预览、导出、在另一项目中审阅后接收 | 人工职责等其他资料的分享；不是整库同步 |

显式索取原文与默认预览分开。预览在完整证据行之间省略，不能因为一条结论较长就剪掉“不适用”的条件。

## 3. 知识模型：一项事实只在一处负责

| 知识 | 回答的问题 | 依据与维护 |
|---|---|---|
| 意图 | 为什么做、什么不做、哪些约束仍然有效？ | 保存项目目标、非目标、决策理由和红线。区分提议、已确认、已取代；只有经人确认的有效结论可以代表项目。 |
| 结构 | 某个模块负责什么、入口在哪里、实际依赖谁？ | 文件、符号和依赖附带位置、内容指纹及可信程度。助手可以补写职责、接口约束和需要一起检查的地方，不能用摘要覆盖解析事实。 |
| 经验 | 哪种做法在什么条件下有效、哪里踩过坑？ | 保存背景、结论和适用条件，可绑定相关文件或符号。一次故障和修复是历史记录；代码变了，提示复核，不抹去经历。 |

例如，“默认离线可用”是意图；某个写入入口实际依赖本地存储，是结构；一次修改让写入必须联网及其修复原因，是经验。三条记录可以互相引用，但不需要把三段正文复制进每次回答。任务画布只记未完成目标、下一步和证据位置；任务结束后，值得长期保存的结论才进入上述三层。

本地库保存记录、检索索引和有方向的关系。事实记录与派生索引分开：索引坏了可以从证据重建，不能因此删除人工确认的意图或历史记忆。对外入口只翻译请求和呈现结果，项目隔离、写入准入、有效状态和预算都在核心处统一判断。

## 4. 先确认项目，再使用知识

**项目身份由稳定标识和已确认的根目录共同确定。** 显示名方便人辨认，但两个同名目录不是同一项目的证据。根目录要先规范化，再与库里记录的绑定比对。指定了库文件，不等于授权把它当成当前项目。

先确定用户选的是哪个项目，再打开它的库。用户明确选择的根优先于启动目录，这样从别处启动助手也能服务正确的项目。没有明确选择时，才从当前目录向上找最近的已绑定根；找不到就提示选择，不因为一次查询而新建库。项目概览和现场恢复的首行都显示可辨认的项目标识和根目录。

初次绑定必须明确选择根并执行 `init`。可以由用户直接操作，也可以由用户已授权的助手按接入步骤代办；根有歧义时先询问，不能靠一次查询自动建库。若请求的根与已有库不符，应在任何创建、升级或写入之前停下；可以报告绑定不符，但不展示另一个项目的标题、路径清单或记忆。旧库缺少身份记录时先确认归属；搬迁已有项目要明确更新绑定；名字相同的副本不得自动认作原项目。

文件、符号、关系与锚点均属于该项目。解析后的真实目标必须仍在根目录内；越界目标不读取，不参与指纹比对。库的位置可以与源码位置不同，搬动库文件本身不会改变知识的归属。

**库放在哪是本机事实，不是项目事实。** 项目的元数据目录只记一个位置提示；打开时照旧按身份核对，提示指向别的项目的库时不加载任何内容。默认数据目录记在用户级配置里，只影响之后新绑定的项目。搬库只经显式命令：独占原库，在目标位置拷贝并校验，切换提示，再删除原文件；切换之前失败，原库不受影响。库不在提示的位置时报告期望位置和重新关联的办法，不建空库。

**知识种类与生效范围是两件事：**

| 范围 | 例子 | 何时使用 |
|---|---|---|
| 项目事实 | 本项目的存储写入不得依赖网络 | 只在绑定项目内检索或展示。不得因评分高或取用频繁而升级成跨项目规则。 |
| 用户偏好 | 用户希望在改动版本历史前先确认 | 仅接受用户明确设定的少数偏好。先用个人设置保存；按稳定主题更新，不写进项目的共享快照。 |
| 本机事实 | 当前机器访问网络需要特定代理 | 默认留在本机，只在相关任务中按需取用。换设备不能视为仍然成立，更不能把地址或凭据当成项目知识发布。 |

项目提议不能改写用户偏好，记忆也不能代替用户对当前操作的授权。暂不建独立的用户记忆库；只有出现需要跨项目检索、修订并追溯偏好历史的真实场景，再重新评估。

用户级配置是一份本机文件，只承载两类本机事实：默认数据目录，以及模型服务的地址、模型名和密钥来源。它不进项目库，不随分享导出。项目库只记这个项目同意过的模型地址（协议、主机和端口），不保存密钥。

## 5. 三种上下文交付

| 入口 | 先回答什么 | 不做什么 |
|---|---|---|
| 启动概览 | 我在哪个项目？当前目标是什么？动手前有哪些红线？详情从哪里找？ | 不拿“最近更新”冒充“必须知道”，不随附全部文件摘要。 |
| 现场恢复 | 上次停在哪里？还有什么待办？上次使用的哪些依据需要复核？ | 不重复整份开场内容，不把扫描窗口之外的条目说成“全部已检查”。 |
| 按需查询 | 这次改动涉及哪些依赖、设计理由或历史经验？ | 默认给摘要、状态和引用；只有明确请求才展开正文。 |

### 启动概览的选择规则

1. 先列项目身份，再列已确认且仍有效的目标与红线，最后才选用户明确置顶、适用于本项目的条目。同一记录只出现一次。没有已确认目标时写“尚未确认”，不拿高分记忆补位。
2. 重要度用于检索排序；确认表示证据已经核对；置顶表示用户希望开工前看到。三者相互独立。普通记忆不能凭高分自荐，已归档、已取代或已撤销的条目不能因曾经置顶而回到开场。
3. 自动开场的**整份输出不超过 800 词元**，包括身份、标题、出处和省略提示。主动请求的完整概览上限为 2,000 词元；实现通过宿主接受的 UTF-8 字节上界保守控制开场与概览。结构查询和 `context` 的实际文本字节限额见第 7、11 节，没有内置词元计量器。先省略正文，再省略次要条目，留下可取回的标识。红线过多时显式提示“还有约束未展示，请先查看”，不能让助手误以为已经看全。
4. 预算依宿主的计量口径对最终文本计算，不按条数或汉字数冒充词元数。无法可靠计量时，自动入口退回到经保守计量的身份与查询入口，不发送一份长度未知的开场正文。
5. 快照属于一个项目的一次会话。重复请求同一快照，只给出相同的标识，不再次注入正文。新增记忆可立即按需查到；显式刷新、切换项目或开始新会话时重新选择。开场后若红线被撤销，不能指望旧文本自行消失：在受该红线约束的操作前重新核对其有效版本。支持会话开始通知的宿主可自动取概览，其他宿主使用同一个显式入口。

## 6. 经验、证据与检索

写入时先处理敏感信息，再做准入和去重。优先保存读源码看不出的原因、约束和复现条件，而不是给函数签名换一种说法。规范化后的标题与正文相同，则返回原记录；标题相似或相同但结论不同，只提示候选，不自动覆盖。决策反转时保留旧结论并指向取代它的新结论。按主题直接更新只适用于偏好这类本来就应有一个当前值的内容。

证据应能回答“谁作出的判断、依据在哪里、确认时是什么版本”。原文位置、文件指纹和确认记录比被检索次数更有用。机器推断或模型整理的内容只能是候选，不能自行成为已确认意图。取用统计若将来需要，只用于分析查找体验，不作为正确性或晋升依据。

默认检索同时照顾中文短词、长词和代码标识。候选先按任务相关性排列，再考虑重要度、时间和源码变化。时间久不等于失效：进度很快过时，而设计约束只有在被取代或撤销时才失效。锚点分别表达“一致”“已变化”“目标不存在”“没有基线，未校验”。缺少可访问的项目根时，不应声称代码没有变化。

可选的模型增强有两组，都默认关闭，关闭或不可用时关键词检索和本地写入照常可用。早先的一组只在小范围内用模型：候选内重排、逐条授权标题的语义查找、从当次文本提炼候选。后加的一组是按项目启用的向量检索与重排，启用后改变默认检索的行为，规则见第 12 节。证据查询最多展开一层相关依据，区分冲突与缺口；只有读者明确请求时取原文。

## 7. 结构索引与影响判断

索引从已绑定的根目录开始，只收纳入管理的源码。**项目用 Git 管理时，纳不纳入以 Git 的忽略规则为准，名字不参与**：没有被忽略的文件就是项目自己认的源码，放在 `build`、`vendor`、`credentials` 或以点开头的目录里也一样。规则取自仓库的 `info/exclude` 和工作区顶层往下各级目录的 `.gitignore`，深层盖过浅层；不读用户全局的忽略文件。“用 Git 管理”指项目根或它的某级祖先目录里有 `.git`，或者根目录有 `.gitignore`。外层仓库若把项目根所在的目录忽略了，它就管不着这个项目，它的规则一条都不用。没有 Git 规则可依时退回内置名单，按名字排除构建产物、依赖目录、隐藏文件和常见私密目录。每次索引都报告这次用的是哪一种范围。

有几样东西不看规则：嵌套项目、目录链接、`.git` 和 `.loom` 永远不纳入。按 Git 规则取范围时，`node_modules` 和带虚拟环境或缓存标记的目录（里面有 `pyvenv.cfg` 或 `CACHEDIR.TAG`）也不纳入，它们不是项目的源码，仓库却未必写了忽略规则；文件名表明是生成物的（`*.min.js`、`*.generated.ts`、`*.generated.js`）只登记，不解析。`.loom/ignore` 只能追加排除，不能把已排除的放行，其他私密位置写在这里。

结构索引只存路径、符号名、导入的写法和行号，不存源码里的值。名字本身像凭据时另有三道保险，判断用的是写入记忆时的同一套脱敏规则：路径像凭据的文件不纳入，因为不能一边展示掩过的假路径，一边拿真路径当定位键；符号名像凭据的只存掩码，别处不能按名字找到它；导入的写法或候选像凭据的只存掩码，标为无法静态确定。

每轮仍需枚举文件，对大小合适的文件计算内容指纹，未变文件不重新解析。超过 1,048,576 字节只登记，不做全文解析。无法读取和语法不完整都属于未覆盖，不是“没有依赖”。范围扫描不能完成时保留上一次成功快照，不发布半次更新。

依赖方向定为“使用方指向被使用方”：解释模块时顺着边找它需要什么；判断影响时反向找依赖它的地方。每条边保留证据位置，并区分可直接确定、只有一个合理候选、无法消歧三种情况。默认影响结果区分展示前两种，不把猜测计入确定影响数。遇到环路不重复展开，多跳查询默认不超过三层。

新增、修改或删除文件时，一次更新替换它的派生记录，并重新核对受影响的引用方。目标改名或消失时，旧关系不能继续显示为有效；不能仅凭同名把历史锚点移给另一个文件。人工摘要记录撰写时的指纹，源码变化后先标为待复核。摘要可分批补写，每批最多 20 个文件；没有摘要也应当能查到已经验证的符号和依赖。

首批覆盖三类项目：有显式模块边界的系统代码、前端脚本、按包组织的动态脚本。随后加入按包和名字组织的编译型代码（Go、Java）、靠包含指令连接的 C 和 C++，以及单文件组件里的脚本。只把能定位的模块声明、导入、包含指令和顶层声明当作静态证据，不追踪每个符号的调用者。一个运行时表达式可能加载多个文件；这时报告无法静态确定。同名候选单列，不参加默认影响遍历。人工职责有独立的复核基线，不能替缺失的依赖作证。

有些目标只在工具约定下成立：TypeScript 源码里写 `./x.js`，实际文件是 `x.ts`；Python 绝对导入的包放在 `src/` 之下。这类候选只按路径拼出，不读打包配置，也不新增确定关系：唯一命中时只算“只有一个合理候选”，与书写的文件并存时算无法消歧。写在函数或分支里的导入不一定执行，即使目标在词法上唯一，也只算一个合理候选。前端脚本里的 `import('…')` 和 `require('…')` 同理：说明符是字面量时按静态导入的规则给候选，写全了文件名也只算一个合理候选；说明符是表达式时仍报告无法静态确定。同样只算一个合理候选的还有两种回退：省略扩展名的导入在脚本文件都落空后才看的 `.vue` 和声明文件；C 的包含指令在使用方旁边找不到时，按路径后缀对上的头文件，因为包含路径写在编译参数里。

Python 的绝对导入还有一个候选根叫“包根”：从使用方所在的目录往上走，目录里有 `__init__.py` 就继续，停下的那个目录。解释器把入口脚本所在的目录放进模块搜索路径，测试工具也这样推断模块的根，所以脚本目录里的同级模块找得到。包目录本身不当候选根，否则包里的 `import openai` 会连到同目录的 `openai.py`。哪些目录是包，由索引从受管文件里数出来交给解析器，解析器仍不碰文件系统；增删一个 `__init__.py` 只让它所在目录之下的 Python 文件重算。经包根找到的目标和其他绝对导入一样，最多算一个合理候选。

前端脚本的裸名导入可能是 `tsconfig.json`、`jsconfig.json` 的 `paths` 定下的别名。解析器仍不碰文件系统：索引把项目里名为 `tsconfig*.json`、`jsconfig*.json` 的配置读出来交给它，配置不算受管源码。一个文件用离它最近的 `tsconfig.json`，同一目录里没有才用 `jsconfig.json`，这是编辑器的做法；那份配置沿 `extends` 取最近写了的 `paths` 和 `baseUrl`，自己没有别名时看它 `references` 的配置。模式的匹配和替换照 TypeScript 的规则，改写后的路径与相对导入一样补扩展名。打包器真正用的别名写在它自己的配置里，要执行才知道，所以经别名找到的目标最多算一个合理候选。任何一份配置有变化，全部前端脚本重算。`include`、`exclude` 和 `files` 不求值，汇总配置引用的几份说法不一时都算上。

Go 和 Java 的引用不写文件路径。文件登记它提供的声明键（Go 是导入路径加包名，Java 是包名）和所属的根，引用方给出“某个键里的某个顶层名字”，索引到声明处去对。解析器仍不碰文件系统：Go 的模块路径由索引读出各级 `go.mod` 后传入，它变了，全部 Go 文件重算。按名字找到的目标要同时满足四条才算可直接确定：写法在语法上确定，只对上一处声明，命中的是书写的目标而不是回退，使用方与目标同属一个根。Go 的根是模块，受构建约束的文件不属于任何根；Java 的根是目录去掉包路径后剩下的源码根。其余的唯一命中只算一个合理候选。只是提到一个名字、项目里又没有对应声明的，与项目无关，不算缺口。同一对文件之间按名字的多处引用，查询只展示行号最小的一处。按名字的查找只为提供声明键的文件登记顶层名字，其他语言的符号不进这张表，改它们的文件不必改写名字索引。

为避免一次收到整张图，文件查询默认一跳、最多三跳。每次最多返回 64 条关系、40 个符号和 24 处未确定引用，每处最多展示 4 个候选；检索触及上限时单独报告。结构文本的 CLI 预览最多 6,144 UTF-8 字节，MCP 预览最多 1,500 字节，按完整证据行省略并统计省略数量；CLI `--json` 保留完整报告，诊断 JSON 不受文本预览上限。字节数不是任意宿主的词元数，快照与核对契约见第 11 节。

## 8. 数据迁移与分享边界

已有记忆从带来源标记的文本页导入，不连接旧系统。默认先预演并列出预计新增、重复、跳过项及原因；明确确认后再写入目标项目。保留可用的旧标识、类型、标签、时间和状态，重复导入不得增加条数。没有历史源码指纹的锚点标为未校验，不拿今天的指纹冒充当时的证据。源资料始终只读。

项目库留在本地。需要分享时只从用户选定的有效目标、红线与经验生成可审阅文本；文件职责仍留在原项目。个人偏好、本机事实和凭据不属于交付范围，不能仅靠自动筛查自然语言，发送人必须逐项核对。接收方先预览差异；相同来源与内容不重复写入，遇到冲突则不写该批记录。

## 9. 后续能力的边界与验收

**跨文件导入。** 导入语句、所属根、可达的模块声明和最终文件是不同证据。只有能从使用方沿唯一且无条件的声明链走到本地目标，才可新增确定关系。只看目录布局、同名文件或源码中出现的包名不够。依赖清单可以佐证某个名字来自外部，不能单独证明一条具体导入没有被本地名称遮蔽。确定的外部项也不是本地入边。中间声明变化时必须撤回失去依据的结论，即使两端文件都没改。按名字找文件的语言里，声明链是清单里的模块路径、文件的包声明和顶层声明；同根是对“一起编译”的近似，读不到构建配置时不能再放宽，跨根的唯一命中只算可能。工具配置同理：`tsconfig` 的 `paths` 说明编辑器和类型检查器怎样找文件，不能证明打包器也这样找，经它找到的唯一命中只算可能。

**确认与复核。** 意图的提议可由助手登记；确认、撤销与取代需要人明确决定，不能由会话工具自行提升状态。人作出决定之后，命令可以由助手代为执行：给助手的提示词写明“先问、得到当次明确同意、再执行带确认开关的命令”，会话工具仍然不提供这些操作。绑定项目和建索引只在本机生成可重建的数据，提示词授权助手直接做。用新意图取代旧意图是一次操作，要么都生效，要么旧结论保持有效。置顶只决定展示次序，不提升可信度。人工文件职责与解析事实分开保存，记录复核时看到的内容指纹；读取、刷新索引或文件暂时失踪都不能替人重新确认。过期摘要可带警示查阅，不当作当前职责。

**恢复现场与追查依据。** 任务画布至少回答目标、接下来做什么、证据在哪里。中断恢复先给未完成任务的入口，已关闭任务不再冒充待办；其他记忆只在其后简列。证据包先给直接命中的编号与出处，再分列人明确记录的支持或冲突、时间或源码变化的提示、尚无证据之处。两条记录措辞不同不等于互相矛盾；没有查到支持或反对，也不等于结论已证实。只有显式记录的关系才可当作旁证，无须把整张关系网放进上下文。

**轻量原则。** 没有宿主可靠计量时，自动入口只给可保守计量的身份和查找入口；连这也无法保证时不注入。支持自动通知的宿主与只能手动调用的宿主都使用同一套选取规则。模型增强既不替人确认，也不作为日常写入、恢复或证据查询的依赖。是否引入增强，先看固定问题上的收益，再单独明确数据范围和启用方式。

可选增强分两条独立路径。第一条只在显式给定的问题和一小批已脱敏候选标题内比较含义，结果标成“候选内重排”，不能说成全库语义召回；留下原关键词顺序以便对照，模型不可用仍返回原结果。第二条只接收用户当次交给它的文本，先脱敏再提炼建议；展示来源并让人审阅，不写库、不确认项目目标。这两条只接本机回环地址，不随项目携带模型地址或密钥。模型不可用与没有相关记忆、没有可提炼结论是不同结果。按项目启用的向量检索可以使用云端模型，它的数据范围、同意方式和回退规则单独定在第 12 节。

不同宿主对词元的定义不同。宿主只有明确声明其文本词元数不高于文本字节数时，才可采用按字节计量的保守上界，并预留快照标识与省略提醒的空间。未声明时不自动发送知识正文；主动按需查询与自动开场互不替代。手动刷新重新选择当前有效内容，不隐式重建源码索引或复核文件职责。

第一版分享只传人明确选定、逐条复核为项目知识的有效目标、红线或经验，先看将离开项目的确切文本，再决定是否生成快照。选项为空等于不导出，不展开关联内容，不附带项目根、历史凭据、用户配置或机器资料。接收方只预览差异；即使选择接收，意图也只作为待审提议，经验保留来源，不静默覆盖或发布到第三方。重复接收同一来源和内容不增加条目。没有被明确选中的记录留在原地。

跨措辞查找与候选内重排是两种能力。若要找回关键词完全未命中的经验，用户需先逐条选定允许参与本地语义查找的有效经验。只将当次问题和这批记录的脱敏标题交给本机模型，不发正文、不越出所选集合。集合有明确容量，超出时拒绝而非悄悄遗漏；撤回授权或归档后立即停止使用。模型不可用时只在相同范围用关键词回退，不能偷偷扩大范围。在固定问题中必须有至少一个“关键词无命中”的反例。

检索时折叠近似项只为节约展示空间，不改变库里的任何一条记录。只有类型、状态、依据和实质正文都一致而标题仅有轻微变化时，才可列出代表项和被折叠的编号；否定、数字、条件、来源或文件不同的记录分别展示。读者可以按编号核对原文，不能把相似当作事实相等或自动消除冲突。

### M1 的第一条可验收路径

M0 曾在确定项目归属前打开或创建库。M1 的第一项改动已经把顺序反过来：先选根，只读核对库的归属，再开放内容。命令行与会话入口使用同一个判断；后续的结构索引也应沿用它。

1. **先验证不会认错项目。** 准备两个同名但根目录不同的空项目，各放一条不同的私有决策。让一方打开另一方的库：应提示身份不符，读取另一方记录数为零，两边数据均不变。再验证从子目录启动、显式指定根和移动项目后的确认流程。
2. **再验证依赖方向。** 在 Loom 自己的测试资料里设一个入口、一个写入模块和一个无关模块。解释入口应找到写入模块；查询改动写入模块的影响应找到入口，但不能包含无关模块。每条结论都要能定位到证据。
3. **最后验证变化会纠正答案。** 去掉这条引用后只做增量更新，旧影响必须消失，无关文件不重新解析。另设两个同名候选和一个无法读取的文件，分别显示为不确定和未覆盖，不能报告成“没有影响”。

这条路径不依赖语义模型、全量人工摘要或自动开场。先证明 Loom 认得对项目、找得对依赖、代码改后能收回旧结论，再扩大覆盖范围。

### 11.1 查询报告与快照发布

结构报告使用 **`contract=2`**，解析语义仍为 **`REVISION=8`**。报告版本描述输出契约，解析修订决定已有结构事实能否继续读取，快照 `generation` 则标识每次成功发布；三个编号不能互相替代。

| 维度 | 当前交付 | 结论边界 |
|---|---|---|
| 查询范围 | 项目绑定、目标、方向、深度，实际检查的文件与引用数 | 一跳和受限遍历只回答对应范围的问题 |
| 快照依据 | 代次、解析修订、完成时间、范围类型与输入摘要；既有 `snapshot_at` 保留 | 时间近、HEAD 相同或修订相同均不证明源码没变 |
| 覆盖 | 受管/未覆盖数量，按原因的未覆盖及未确定引用，排除目录/文件和凭据路径拦截统计；`known` 标明是否有完整记录 | 排除和未覆盖不能补成“已检查”，旧记录缺失不能补零 |
| 本次核对 | `verification.files/inputs/skipped` 分列一致、变化、消失、未知或不可核对及超额项 | 核对只覆盖选出的文件和输入，不查出新文件，也不代表全项目实时一致 |
| 证据性质 | 静态确定、可能、多个候选、未确定原因和人工职责复核状态 | 排序、同名和人工摘要不能把可能关系升级成解析事实 |

显式索引先取得写锁，再扫描并在同一事务内发布结构事实、代次、覆盖和输入基线。失败保留上次快照；成功的无改动刷新也产生新代次。读取从一个数据库读事务取得完整旧代次或完整新代次，不混用正在发布的记录。结构现场核对在读取事务结束后进行。

代次由快照表的插入/更新触发器递增。安装触发器后，同修订旧二进制写快照也会推进代次；新增发布记录若没有同代更新，覆盖明细就变为未知，不复用上一代数据。旧库没有新增表或代次时可读取兼容修订的旧事实，提示显式 `loom index` 补齐；查询不建表、不升级索引。修订不兼容时拒绝读取。

### 11.2 有界现场核对与三类结论

现场核对选择目标、已返回关系两端、问题来源及 Rust 声明链，最多 32 个源码文件；源码和普通配置单文件上限 1 MiB，忽略规则单文件上限 256 KiB。Go/ECMA/Rust 每类配置完整集合不超过 16 项时逐项比较，超出则只查相关祖先目录并标记不可完整核对。这些是文件数量和单文件边界，不是整次查询的累计读取字节预算。

输入基线按五类处理：`rules` 保存范围与忽略规则摘要，`go` 保存 `go.mod`，`ecma` 保存 `tsconfig*.json`/`jsconfig*.json`，`rust` 保存 `Cargo.toml` 的内容指纹；`python` 从受管快照取得祖先 `__init__.py` 的存在性基线，判断包状态而非以内容变化重定包根。相关位置原来不存在的规则、配置和包标记也参与存在性比较。旧基线缺失保留未知。

核对复用扫描准入，只沿路径祖先检查，不扫描兄弟目录。绑定、忽略规则、嵌套项目、链接/联接、文件类型和凭据规则继续约束现场读取；目录剪枝只计边界，不读取被排除内容补数量。越界、超额、权限或安全检查失败时保持不可核对。查询不隐式索引、不持久化核对结果，也不新增后台扫描。

`conclusion.verdict` 有三个值：

- **`found`**：快照内查到关系，仍可带 `gaps`；有命中不等于关系已全部找齐。
- **`none_in_snapshot`**：仅在本次快照、指定方向和受管范围内未查到本地关系，不能扩大为“当前项目不存在”或“当前代码没有影响”。
- **`gap`**：没有关系且存在妨碍判断的缺口，例如未索引、目标不在范围内、未覆盖、未确定引用、查询截断或已知文件/输入变化。

出边依据实际查过的文件和引用，入边还要求全快照的未覆盖、未确定引用及覆盖明细允许否定。未知或不可核对状态在 `verification` 单列；即使可给 `none_in_snapshot`，也只是否定所读快照，不能借局部核对升级成当前全项目结论。检索截断与展示省略分开，文本按完整证据行省略并保留统计与续查。

### 11.3 显式只读 `context`

CLI 与 MCP 已提供同名入口，共用 `loom-core` 的选择和装配层。调用方明确给出项目内相对文件 `target` 和 `mode=explain|impact`；可选 `question` 是最多 512 UTF-8 字节的空格分隔经验关键词，不带空格的中文整句按一个词检索。`depth` 为 1..3、默认 1；`budget` 为 1..6144、默认 1500，按最终文本的 UTF-8 字节计。

一次交付固定分为四区：

1. **身份与约束**：项目标识、任务、当前有效且已确认的红线与非目标；提议不生效，每类检索最多 64 条，有遗漏就提示先查约束。安全且预算容许时补完整项目根。
2. **结构**：快照代次、时间、方向对应的关系；确定、可能与未确定引用分开，保留使用方行号及 U-1 的结论与核对状态。
3. **职责与经验**：人工职责及当前/需复核/消失/不可核对状态；相关有效经验的类型、编号、日期、来源与复核提示。
4. **缺口与续查**：来源失败、未覆盖、未确定、变化、检索窗口与预算省略，以及可继续取回的命令、目标或编号。

结构、约束、职责与经验基线从同一数据库读视图取得；结构核对在视图内取得基线、在事务外检查现场，不承诺整个文件系统的一致时点。一类来源失败时继续交付其余可用分区，并保留失败说明；不把失败写成零条。

相关经验先取锚定本文件的有效记录，最多 5 条，再按关键词去重补充最多 5 条。省略 `question` 时默认用**带扩展名的文件名**补查；文件名不足 3 个字符则不补查，显式空关键词也不回退成最近记忆。来源分别写“锚定本文件”“关键词命中”“提到本文件名”，文字命中不冒充锚定。关键词复用已有排序和近似项折叠，候选查询窗口 50 条，窗口外条数未知时保留提示。

核心先预留身份、状态、缺口、约束遗漏提醒和续查，再装入完整脱敏行。首条也受预算约束，放不下则整行省略，不截掉条件或否定词；检索省略与预算省略分别统计。长标题保留可取回编号，必要内容都放不下时拒绝预算并报告本次最低需求。已有深度、关系和引用数限制不随文本预算扩大。

CLI 与 MCP 返回同一份 `ContextReport.text`，预算包括换行、来源、状态和续查。CLI `--json` 另给四区、`bytes`、`omitted.budget/retrieval`、`gap_codes` 与完整结构报告，整个诊断 JSON 不受 `text` 限额。当前不内置词元计量；字节成本、诊断 JSON 和 MCP 封装分别计量。

`context` 只在显式请求时运行，不自动猜目标、刷新索引、保存 `question`、启动模型或确认知识。`overview`、`refresh`、`resume` 及自动开场沿用原有规则；当前没有重复交付账本或自动语义扩张。

### 11.4 固定评测与本机验收

`eval/` 已冻结 Rust、JS/Vue、Python 三个样本，120 条标签、38 个问题（结构 26、记忆 4、任务 6、预算拒绝 2），并有独立质量、资源运行和比较脚本。固定版本、文件摘要与范围输入须相同；样本只在隔离副本中读取，不执行样本代码，不依赖下载、网络或模型。Python 的 `oh-memos` 仅为源码样本，不是服务依赖。

**Precision 衡量已报告关系的正确率，召回衡量标注正例是否被连上，两者分开。** 脚本在标签覆盖的来源、行号和目标上，按报告声称的 exact/likely 计算 precision；漏连归召回，标签类别的命中比例另列。reported exact ≥98%、likely ≥95%，逐条无新增错误/丢失、逐语言召回不退步；没有对应类别记 N/A。标签之外的关系不由这项指标穷尽。

固定问题分别核对事实与报告契约，错报不存在要求零；工程边界另由仓库测试把关。六个任务用同一候选版本的原有多次查询与 `context` 比较：正确依据、条件和缺口不丢失，请求次数或最终交付字节严格减少。词元只有明确分词口径才记录，文本变短本身不证明答案更准确。

正式资源同场逐轮 AB/BA 轮换至少五轮，分列全量、无改动、单文件修改、解释和影响查询的中位数、范围及峰值工作集；每个样本/版本另开 serve，固定调用后空闲至少 30 秒再测工作集。单版本试跑不是正式对照，耗时增幅超过 10% 要给出解释。

## 12. 库位置、助手接入与可选的向量检索

三项都在 2026-11-26 实现，验收记录见 [验收清单](ACCEPTANCE.md)的“库位置、助手接入与可选的向量检索”。解析修订和报告契约不变。

### 12.1 库的位置

定位顺序是：命令行显式给的库 ＞ 项目记住的位置 ＞ 项目里的默认位置。记住的位置是元数据目录里的一行绝对路径，与项目标记用同一套检查：必须是真实元数据目录里的小型普通文件，不能是链接，内容不合规就拒绝，不猜。

- **位置提示不是授权。** 打开时照旧核对库内身份、根目录和标记。建连之后再读一次提示，位置在这期间变了就让调用方重试，不把刚被搬走的旧库交给会话。
- **默认数据目录**只在全新绑定、又没有显式指定库时生效，库建在“数据目录／项目标识”之下。核心的绑定逻辑不读用户配置，由命令行层读了传进来，进程内的调用和测试不受这台机器配置的影响。
- **搬库**先取绑定锁，再要求自己是唯一的连接（把日志模式切回回滚模式，有别的连接时切不动），然后独占原库。拷贝写在目标目录的临时文件里，校验完整性、项目身份和每张表的行数，做完检查点才改名发布。位置提示用“临时文件加改名”原子切换，目标就是默认位置时删除提示。最后删除原文件，删不掉只报告、不算失败。
- 目标写的是目录还是文件，看扩展名：只有写明了库文件扩展名的才当作文件。用户说“搬到某个目录”而目录还不存在时，不能建出一个与目录同名的库文件。
- 记下来的路径先规整掉 `..` 和混用的分隔符，不解析链接；给人看的路径去掉系统的规范化前缀。

不检测网络盘和同步目录，只在文档和助手步骤里提醒。

### 12.2 会话服务与助手接入

会话服务启动时只固定“怎么找项目”（启动目录和显式参数），不固定找到的库。每次工具调用重新定位、打开并核对身份，用完关闭连接。会话记住第一次核对到的项目身份，之后换成另一套有效身份也拒绝。

- **没绑定也能启动。** 握手成功，不给开场，工具列表里只有恢复现场这一个入口。它的回答是定位器的原始原因加一句引导：去运行随程序分发的接入步骤。“还没接入”由定位器用专门的错误类型表达，与库丢失、身份不符分开；后两种不引导去建库。
- **绑定之后不用重启。** 同一个进程下一次调用成功时，向宿主发一次工具列表变更通知，并在恢复现场的输出末尾加一行就绪提示（只加这一次，仍在整份预算之内）。宿主不刷新工具列表时，助手先用同名的命令行。
- **不长期占着库。** 会话空闲时别的进程可以独占库，所以搬库和备份不用先关会话。代价是每次调用多一次定位和打开。

接入步骤有四个主题：接入项目、搬库、启用模型、给助手的提示词。它们编进程序，提示词只需指向它们，步骤跟着版本走。有测试保证步骤里写的每条命令都是这个版本能解析的，[中文手册](../README.zh-CN.md#交给助手)里的提示词与程序输出的是同一段；[英文使用手册](../doc/MCP/README.md#workflow)另给英文工作流。

提示词划了三条线：绑定和建索引由助手直接做；意图生效、职责复核、搬库、启用模型、分享和删除要先问，得到当次明确同意后助手才替人执行；密钥不经过对话。

### 12.3 可选的向量检索与重排

**配置在用户级，同意在项目级。** 模型的地址、模型名和参数写在用户配置里；密钥来自环境变量或单独的凭据文件，不从命令行参数接收，任何输出都不显示。每个项目要显式启用一次：先预演发到哪、发什么、有多少条，确认后才记下同意。同意绑在模型地址（协议、主机和端口）上，配置换了主机就视为没有同意，向量和重排各自检查。

| 方面 | 规则 |
|---|---|
| 协议 | 向量是 OpenAI 兼容的 `embeddings`，重排是 `rerank`（查询加候选文本，返回下标和相关度）。别的形状不支持 |
| 地址 | 回环地址算本机，其余算云端；云端必须用 `https`。不走代理，不重试，不跟随重定向 |
| 时限与大小 | 单次请求有绝对截止时间，默认 8 秒；响应体有上限。失败只报分类，不带请求或响应内容 |
| 发送范围 | 有效经验脱敏并单行化后的标题和正文，每条最多 2,000 个字符；脱敏后仍像凭据的整条不发。查询词同样处理。重排最多 24 条 |
| 不额外附带的字段 | 不从库中另取编号、锚点、文件路径、标签、项目名、根目录、项目标识、意图、文件职责或任务，也不读取源码文件发送。**自由文本是例外**：查询或经验标题、正文里若本来就写有路径、项目名、代码片段或其他敏感业务内容，凭据脱敏并不会自动移除这些内容；它们可能随文本到达所选服务。 |
| 向量 | 存在项目库里，记下“哪个地址的哪个模型、什么维度”和所发文本的摘要，任一对不上就算过期。它是派生数据，可以清空重建 |
| 身份与同意 | 发送前和等待后都重新核对项目身份和同意；等待期间不持有数据库事务 |

启用之后的一次检索：取关键词候选和向量候选各 30 条，按倒数排名融合；配了重排且地址在同意范围内时，把前 24 条交给重排。名次换算成相关度之后，重要度、新鲜度、源码变化这几个系数以及排序、折叠和条数截取，都与关键词路径用同一段代码。输出的第一行说明这次是怎么查的。新写入的经验在下一次检索的那个向量请求里顺手补建。

**回退。** 模型任何一步失败，都退到上一步能给的结果并说明原因分类；检索本身不因此报错。项目没启用、查询为空（列最近的记忆）时，输出与没有这项功能时逐字节相同，并且不发任何请求。`context` 不调用模型。

**本机模型不放进进程。** 向量由本机的模型服务提供，Loom 可以触发它下载模型；重排要另起一个带重排接口的本机服务，或用云端。模型权重不驻留在 Loom 进程内；这不等于版本间空闲内存不变。本机方案需要另装模型服务，该服务的内存也不计入 Loom 进程的工作集。

早先的三个小范围入口不变：只发标题、最多 12 条、只连回环地址、用环境变量开启。

**限制与未测。** 真实模型的检索收益没有测过，所以默认关闭。向量检索总会给出最接近的几条，没有相关度下限。本地多出的耗时随经验条数线性增长。这些列在[待办清单](plan/BACKLOG.md)。

### 13.3 顺序与范围

先对齐开场和发送告知，不让助手漏读红线或用户误判外发内容；再补可复现的锚点和结构缺口。真实模型对照与宿主、净机验收分别进行，**流程跑通不能代替收益，登记成功不能代替使用验收**。

另行排期的方向（Vue 模板组件、目录聚合、U-4 符号版本比较、Markdown 文档检索等）不是上述验收的前置条件。MCP `roots` 回退、`.env` 显式导入、`loom setup` 和 dsh 薄插件是后提的 D-5 至 D-8，不是已交付命令。整库同步、跨项目私人知识汇总、常驻扫描和完整运行时调用图仍是不做项。
